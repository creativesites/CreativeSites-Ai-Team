# ADR-KI-003 — Hybrid retrieval with a replaceable embedding provider; no vector DB

**Status:** Accepted. **Decision.** FTS5 + embeddings fused with RRF; authority/status/recency re-ranking; permission filtering before output. Embeddings behind `{id, version, dim, embed()}` with model/version stored per vector; swapping triggers incremental re-embed (`setEmbeddingProvider`). Default provider is a deterministic local feature-hashing embedder — **lexical-semantic, not neural** (handles inflection, shared stems, near-spellings; not synonyms). **Why no vector DB:** corpus is local and small; brute-force cosine is exact and simple; revisit when `ki_embeddings` > ~100k vectors or p95 search > 300 ms (measure first). **Consequences.** Search quality is bounded by the provider until a real model is plugged in; the interface and tests (`relevance corpus`) are ready for that.
