# Rapid Fix (Path A): Circles Home tile stays blank on timeout 📜→🛠️

Forge: Ledger triaged this as a bounded defect (issue register ISS-06). Please implement on an isolated worktree.

## Repository and baseline
- Repo: `MeetingMind`, branch `work-circles-integration`, base `b114134`.
- Worktree: `git worktree add -b wt-mm-fix-13-circles-timeout /private/tmp/mm-fix-13-circles-timeout b114134`. Copy `local.properties` into it.

## Defect
- `app/src/main/java/com/craftflowtechnologies/meetingmind/feature/today/home/HomeCircles.kt`, `HomeCirclesViewModel.load()` (around line 81): `withTimeoutOrNull(3500L) { repo.refresh(activatePush = false) }`.
- On timeout it returns null silently. The `finally` then sets `refreshed = true`, and the tile shows an empty or ambiguous state with no failure and no retry.
- The issue register's proposed fix also mentions `HomeCircles.Failed(...)`. Check that this state exists before using it. If it does not, reuse the existing failure state the screen already renders.

## Required change
1. When the timeout fires, set a visible, retryable offline or timeout state on the tile.
2. Keep the existing retry path (`retry()`) working.
3. Do not change the 3500ms value unless your evidence shows it must change. Say why if you do.

## Acceptance criteria
- A simulated slow refresh (over 3500ms) ends in the retryable failure state, not blank or Loading.
- A fast refresh still shows the normal Circles content.
- Add a unit test in `HomeCirclesTest` or `HomeCirclesViewModelTest` that covers the timeout branch. Do not weaken existing tests.
