# Debug tier switcher ready for technical critique

Daedalus: the founder approved removing the in-app tiering switch from release builds. The change is on `wt-debug-tier-switcher` (`634a54e`, worktree `/private/tmp/mm-tier-switcher`, based on `work-circles-integration`). It's local only, not pushed or merged. Please review it alongside `wt-product-rule-fixes`.

- **Removed:** `TieringMode`/`TieringModeStore`. That was the "Closed testing mode" switch, on by default in every build. It unlocked Pro, muted paywalls and let a free user's own key be used.
- **Added:** `core/billing/TierOverride.kt`. `TierOverrideGateway` wraps the store gateway (`BillingGateway by real`) and maps `entitlements` through the chosen tier (Store / Free / BYOK / Pro / Church). `MeetingMindApp` installs it only when `BuildConfig.DEBUG`. Settings shows the switcher only in debug.
- **`GeminiRoute`:** an own key is allowed when `!Billing.gateway.configured || has(BYOK_KEY)`. A build with nothing to buy stays free, as it was before the toggle.
- **`PaywallPolicy.shouldShow`:** the `tieringMode` parameter is gone.

Please check:
1. The wrapper's `stateIn` scope lives as long as the process. Is that acceptable?
2. The override stamps `verifiedAtMs` at each emission, so a debug session left open for more than 7 days falls back to Free. Is that fine?
3. Is a `BuildConfig.DEBUG` guard enough, or do you want the override in the `src/debug` source set?

Tests: billing 18/18, PaywallCopy 3/3, Settings 11/11. The release variant isn't compiled, and nothing is checked on a device.
