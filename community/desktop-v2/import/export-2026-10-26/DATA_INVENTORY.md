# v1 → v2 data inventory and export (2026-10-26)

One-time, deterministic export produced for the MyaOS Desktop v2 identity/team import
(shared task `task-6`, Phase 1). Nothing in this folder is generated by the v2 runtime;
it is an input for the Lead to import (or reject) and a record of what v1 data exists.

- Generator: `runtime/scripts/import-identities.mjs` (plain Node ESM, no dependencies).
- Regenerate: `node runtime/scripts/import-identities.mjs`; verify: `--check`.
- Sources are read **read-only**; the v1 DB is opened with `sqlite3 -readonly`.
- The export is a snapshot of the machine state on 2026-10-26. The folder name carries
  the date; no generation timestamp is written inside the JSON files.

## 4. What is lost if `data/myaos.db` is untracked

This is the highest-risk item for the Lead before Phase 4/cut-over.

- The v1 live store is **tracked in `main` and currently dirty**: `git status` shows
  `M data/myaos.db` in the main working tree. The committed blob at `HEAD`
  (`main` = `9d287fe`) is the **stale** DB (13 identities / 37 tasks / 2 teams /
  21 evidence / 110 events / 5 projects), not the live one.
- The worktree copy at `<worktree>/data/myaos.db` is that same stale blob
  (sha256 `fc31ae4cf36135e9f64309bb1f5f1537ae71e0f163bcd24ab4bc32b9001c6ac5`,
  13 identities). **Never import from it.** The script deliberately resolves the
  main-tree DB for this reason (`--main-root`/`--db` can override).
- If the DB is untracked in Phase 0.7 **without a backup**, any of these loses the live
  state: `git checkout -- data/myaos.db`, `git clean -fdx`, `git stash`,
  a fresh clone, or accidentally committing the old HEAD version. The live-only rows are
  13 identities (`cinder, daedalus, forge, gantry, hermes, ledger, mira, orion, sentinel,
  sol, synapse, themis, vega`), 8 tasks (`MM-B01`…`MM-B05`, `TASK_MM_001`…`003`),
  1 team (`meetingmind`), 1 project (`proj_meetingmind`), plus all newer evidence/events/
  token/fact rows — i.e. the entire MeetingMind paid-launch and DogForce squad history.
- The v1 test suite (`tests/intelligence_layer_upgrades.test.js`) writes the real
  `data/myaos.db`; until it is made hermetic (Phase 0.7), a test run can overwrite/
  duplicate live state.
- **Recommended mitigation before untracking:** copy the binary DB out of git and record
  its hash, e.g. `cp data/myaos.db ~/.myaos/v1-archive-2026-10-26.db` and
  `shasum -a 256 data/myaos.db` (expected
  `f031e9fd1e86af8cc26961445dab1ec65bc1c9348ecca66234b2b11dd67ad0ee`), or
  `sqlite3 data/myaos.db ".backup ~/.myaos/v1-archive-2026-10-26.db"`. Keep the copy
  outside the repo; this export folder preserves the identity/project/task/token
  structure but **not** the evidence payloads, events stream, facts, provenance log,
  transcripts or the other ~50 v1 tables.
- `data/provenance.log` is also tracked-and-modified (`M`) and not versioned separately;
  archive it with the DB.

## 6. Merge and resolution rules (no silent guesses)

1. **Identity set = DB ∪ agents.json.** 26 + 25 − 23 = 28. DB-only: `meridian`, `sage`,
   `test_spec`. agents-only: `sirius`, `wren`. Registry (23) is never allowed to delete a
   machine-registered identity; it only adds coverage conflicts.
2. **Precedence: `data/myaos.db#identities` > `community/agents.json`** for name, symbol,
   primary domain, team, lane, provenance, liveness. Every divergence is a `conflicts[]`
   entry with both raw values.
3. **Lists are unioned**: `capabilities = DB declared_capabilities ∪ agents.json
   declared_capabilities/capabilities`; `responsibilities` likewise; `repositories` from
   both. Sorted, deduped.
4. **`role`** = primary domain (the stable short title for `Identity.role`); the full
   declared responsibility list stays in `responsibilities`.
5. **Provenance mapping** (`provenance` keeps the raw v1 string; `evidenceClass` is the v2
   `EvidenceClass`):

   | v1 `confidence_provenance` | v2 `evidenceClass` | rule |
   |---|---|---|
   | `OBSERVED` | `OBSERVED` | runtime observed |
   | `VERIFIED_OBSERVED` | `OBSERVED` | v1 observed, **not** independent re-verification (D9) |
   | `ATTESTED` | `ATTESTED` | attested claim |
   | `DECLARED` | `DECLARED` | claimed |
   | `UNVERIFIED_DECLARATION` | `DECLARED` + flag | claimed, explicitly unverified |
   | `UNKNOWN` / null | `UNKNOWN` | no claim |

6. **Avatar marks** are a curated subset of `AVATAR_MARKS` from
   `apps/desktop/src/components/app/avatar.tsx`. Unmapped symbols use the component's real
   monogram fallback (`avatarMark: null` + `avatarFallback: "monogram"`); the fallback is
   recorded per identity in `avatarNote`.
   Mapped: `✦ ✧ ✶ ✺`→star, `🛡️`→shield, `⬡`→hex, `◈`→diamond, `⏣`→triangle,
   `👁`/`☀`→ring, `♊`→bars, `📦`→square, `🪽`→wave, `🧭`→arcs.
7. **Avatar colours** are team-semantic (deterministic, one per team):
   creativesites→teal, meetingmind→violet, deployfleet→blue, unknown team→graphite,
   owner→amber. All values are in the supported `AVATAR_COLORS` set.
8. **Adapter preference** is only written when the sources support it, with a confidence
   marker: `declared` (`gemini_cli`→gemini), `inferred` (`atlas, kael, lyra, vega, vela,
   wren`→claude from the v1 `/tmp/cc-socks/<pid>.sock` session convention), or
   `unknown`/null (everything else; `antigravity` is an IDE name, not one of the four v2
   ACP adapters, so it is null). `adapterEvidence` quotes the basis.
9. **`seats` is `[]` for every identity** — v1 has no council-seat assignment row for
   these identities (review §2.5 says the seat model must move into the store anyway);
   nothing was invented.
10. **`liveness` and `livenessSource` are copied v1 snapshots** (`LIVE/OFFLINE/UNKNOWN/
    SELF_REGISTERED` + `evidence_source`); they are not probes. v2 must probe adapters
    (D5) and never render these as current.
11. **Owner** is produced only from D7, not merged with any agent row.
